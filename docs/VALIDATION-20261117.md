# 2026-11-17 整合验证

环境：Windows，Python 3.10.4，SQLite 3.37.2；合成实验，非生产容量验证。

- 主应用及统一启动器：118 项测试，117 通过，1 跳过。跳过的是 Windows 当前账户无软链接创建权限的归档路径安全测试；没有调整系统权限，不能称该项已验证。
- 原本机房型策略实验室：51 项通过。
- 房型策略：4 组固定种子共 712 笔请求；接受 243 / 282 / 247 单，586 / 673 / 601 间夜，实验所定义违规 0；复现原结果。
- 具体房间：500 个确定性场景、20,000 次原始分配；逐步检查同房、资源、容量、预算及保护约束，并重试每个请求和反向房间顺序回放，通过。
- SQLite 审计：12 进程争抢最后一间房仅 1 笔成功；12 进程争抢共享辅助资源仅 1 笔成功；相同请求重试只生成 1 次预订事件；取消并发只释放一次。
- 崩溃实验：预订和取消各 3 个提交前后注入点，通过恢复及同键重试核查。10 轮 × 12 进程冷初始化成功。
- 状态机：5 个种子 × 200 次新预订、重试与取消混合操作，全部通过。

发现与修复：

1. 主应用原来要求 Python 3.11+，本机房型版本使用 3.10。锁冲突处理在 3.10 上引用缺失 sqlite3 常量，掩盖原本的数据库忙错误。新增兼容识别：3.11+ 优先使用扩展错误码，3.10 仅识别明确的 SQLite 锁消息；缺表等错误不误判为锁等待。补充单测，数据库审计重跑通过。
2. Windows 文本输出换行导致合成输入无法逐字节复现。生成器改为明确 LF，保留原数据，逐字节测试通过。
3. 软链接权限不足显式记录为测试跳过，而非假报成功。

统一验证入口运行目录：`results/integration-20261117T040252430744Z/`。数据库审计原始结果在 `results/sqlite/independent/`；这些运行目录不上传数据库。原本机文件 SHA256 清单在 `local-source-manifest.json`。

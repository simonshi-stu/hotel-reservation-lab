# 可审计的逐日保护库存策略回放

第一阶段基于 main 的具体房间分配引擎，**不依赖或修改尚未合并的 PR #3 房型实验室**。不迁移数据库、不修改已存在预订，不提供线上生产酒店服务。

## 使用

```bash
python -B -m hotel_sim.replay --input data/week.json --output results/week-replay.json
python -B -m hotel_sim.replay --input data/upgrade_counterexample.json --protection schedule.json --output results/custom-replay.json
```

`schedule.json` 为完整替换的保护计划，例如：

```json
[{"room_type":"deluxe","date":"2026-12-08","count":1}]
```

- 不提供 `--protection`：保留输入场景中的保护计划。
- 传入 `[]`：取消全部保护；未列出的日期/房型按 0 处理，不是增量更新。
- 只支持高于最低等级的房型；拒绝重复键、非法日期、负数、布尔数量、超出该日可用房量等配置。
- 保护量限制的是**低房型升级后**剩余高档房量，原生高档需求仍可使用保护库存。它不是承诺每天永久留空的房间数。
- 输出文件必须尚不存在，避免覆盖证据或输入。每次比较三策略使用相同初始房间、需求顺序和输入，不合并前一次预订状态。

## 可解释证据

结果包含原文件 SHA256、完整有效输入与规范化 SHA256、随机种子（如果场景提供）、实际处理顺序、每种策略的逐单决定、每晚房量/加床/婴儿床增减与剩余房型库存。拒绝请求不扣减资源。

拒绝码来自候选房间检查，可能同时有多个原因，**不是唯一因果归因**。例如 `PROTECTED_INVENTORY` 表示至少有候选升级触及保护线；不能据此保证取消保护就必然成功。

输出证据状态 `executed_simulation` 只表示该次代码实际运行，不表示真实酒店数据、生产性能、全局最优或盈利保证。数据来源标签由输入提供，不是对任意外部文件的真实性认证。

## 2026-11-19 云端实跑

见 [机器可读摘要](replay-evidence-20261119.json)。以下严格/自由升级/保护升级顺序固定。

- `week.json`：75 笔合成请求，8 间房、10 夜，停用房晚后 77 可用房晚。接受 **26 / 27 / 27** 单，与原基线一致。
- 三单反例，同一输入和 A→B→C 顺序：取消保护时“保护升级”实际接受 **1** 单（A，两晚）；每日为 deluxe 保护 1 间时接受 **2** 单（B、C，各一晚）。两者均售出 **2 房晚**，接受订单数提升并不等于房晚入住率提升。
- A 请求标准房住两晚，但只有一间豪华房可用。自由升级先占两晚，使后来的两笔原生豪华房需求被拒。保护阻止 A 占用该资源，B/C 随后成功；这是人为构造反例，不是总体收益结论。
- 只在第二晚保护也足以阻止 A 的整个两晚预订；没有部分入住或部分扣减。原生请求 C 仍能用掉保护房量。

旧 **4 组合成场景、712 笔需求**属于 PR #3 中的另一个房型模型。本增量没有修改它，也不把本次 75/3 笔具体房间结果与它直接比较。

## 验证及边界

```bash
python -B -m unittest discover -s tests -p test_replay.py -v
python -B -m unittest discover -s tests -v
```

新增 8 项聚焦测试覆盖逐日保护、禁用保护、原生需求使用保护量、双晚原子拒绝、非法配置、输入不变、重复运行字节一致、覆盖文件保护与原有两组基线不变。完整套件见 PR 中实际执行结果。

本阶段是可复跑的云端代码/CLI接口和 JSON 证据输出；尚未新增网页交互，也没有把两套分配内核融合。

云端 Python 3.12.14 实际验证：完整 **121 项测试全部通过，无跳过**；其中新增 8 项回放测试全部通过。75 笔场景三策略售出房晚分别 **43 / 47 / 44**，可用房晚为 77。保护升级与自由升级接受订单同为 27，但房晚少 3，说明保护不能宣称在所有目标上更优。
